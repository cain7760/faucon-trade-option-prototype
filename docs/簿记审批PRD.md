# 簿记审批 PRD

| 项目     | 内容                             |
| -------- | -------------------------------- |
| 功能名称 | 期权簿记—簿记审批                |
| 版本     | V1.0                             |
| 状态     | 待业务确认                       |
| 适用角色 | 交易员、簿记操作人员、系统管理员 |

## 1. 背景

期权交易完成簿记后，猎盈簿记系统、BCT 系统及簿记历史数据之间可能出现状态或字段差异。交易员需要在同一页面识别异常、查看证据、补充处理说明，并完成作废、维护或历史修改确认，确保最终簿记数据可追溯。

“历史数据修改”属于簿记审批的一种异常类型，与“簿记作废”“BCT 撤销”“数据不一致”并列，不单独建设功能模块。

## 2. 目标与边界

### 2.1 目标

1. 集中展示待处理的簿记审批异常，并支持按交易维度快速定位。
2. 支持对不同异常类型执行对应处理，保留处理原因与最终处理结果。
3. 对历史数据修改提供原始值、修改值和提交时间等可追溯证据。
4. 处理完成后，异常总数、类型统计和列表数据同步更新。

### 2.2 本期不包含

1. 已簿记交易的录入与完整修改流程。
2. BCT 或猎盈外部系统的真实接口联调、消息重试和补偿机制。
3. 多级人工审批流、审批人转交和审批意见会签。

## 3. 角色与职责

| 角色       | 职责                                                              |
| ---------- | ----------------------------------------------------------------- |
| 交易员     | 查看异常明细，完成簿记、作废、数据维护或历史修改的同意/拒绝处理。 |
| 业务人员   | 在已簿记数据上发起业务修改；系统据此生成历史数据修改异常。        |
| 系统       | 汇集异常、计算统计、记录处理结果，并在处理完成后更新异常状态。    |
| 系统管理员 | 配置角色权限、查看处理记录和处理日志。                            |

## 4. 页面入口与信息架构

入口：`期权 > 期权簿记 > 簿记审批`。

页面由以下区域构成：

1. 异常概览：异常总数及四类异常统计卡。
2. 条件筛选：交易编号、背靠背合约、开平类型、交易日期。
3. 异常列表：展示异常交易及处理操作。
4. 异常明细：展开某条记录后展示字段级证据。
5. 处理界面：按异常类型展示维护弹窗、作废确认框或簿记处理抽屉。

## 5. 异常类型

| 异常类型     | 触发条件                                                             | 处理方式                                                           |
| ------------ | -------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 簿记作废     | 我方簿记已作废，BCT 侧已撤销。                                       | 打开簿记处理抽屉，补充必填信息和覆盖原因后保存或簿记。             |
| BCT 撤销     | BCT 已撤销，我方尚未同步处理。                                       | 发起作废确认；确认后作废我方对应开仓或平仓簿记。                   |
| 数据不一致   | 双方均存在交易数据，但一个或多个字段值不同。                         | 选择猎盈值或 BCT 值作为最终值，填写覆盖原因并确认维护。            |
| 历史数据修改 | 我方当前簿记数据与历史数据不一致，通常由业务人员修改已簿记数据导致。 | 查看修改明细，选择同意或拒绝；同意后修改值生效，拒绝后恢复原始值。 |

## 6. 异常概览与筛选

### 6.1 异常概览

1. 展示异常总数、簿记作废、BCT 撤销、数据不一致、历史数据修改五张统计卡。
2. “异常总数”代表全部类型；默认选中，底部显示 2px 蓝色状态条。
3. 点击任一类型卡，仅筛选该类型的异常列表；再次点击已选类型卡取消筛选并恢复全部类型。
4. 选中类型卡底部显示 2px 的对应语义色状态条；统计卡数量不因类型卡筛选而变化，仅受其他筛选条件影响。
5. 支持手动刷新与每 30 分钟自动刷新；刷新后展示最近加载时间。

### 6.2 条件筛选

| 条件       | 控件       | 规则             |
| ---------- | ---------- | ---------------- |
| 交易编号   | 文本输入   | 支持模糊匹配。   |
| 背靠背合约 | 文本输入   | 支持模糊匹配。   |
| 开平类型   | 下拉选择   | 可选开仓、平仓。 |
| 交易日期   | 日期选择器 | 按单日精确匹配。 |

1. 不单独提供“异常类型”下拉筛选，类型筛选由异常概览统计卡承担。
2. 点击“查询”后应用条件并回到第一页。
3. 点击“重置”后清空所有条件、取消类型卡筛选并回到全部类型。

## 7. 异常列表

### 7.1 列表字段

| 字段       | 说明                                               | 展示格式                                                     |

| 异常类型   | 展示异常标签及语义色。                             | 枚举标签。                                                   |
| 交易编号   | 当前异常对应的交易编号。                           | 编号规则待定。                                               |
| 背靠背合约 | 对应背靠背合约编号。                               | 详见 10.2。                                                  |

| 标的代码   | 交易标的代码。                                     | 来源系统传入的标的代码；组合展示标的时使用“标的名称(代码)”。 |

### 7.2 分页与可视区

1. 使用组件库分页器，默认每页 100 行。
2. 展示总条数、上一页、页码、下一页。
3. 表格可视区域占满卡片剩余高度；分页区与页面背景边缘保持 20px 间距。
4. 当行数超过可视区时，表头、固定列和操作列保持可用，表格主体内部滚动。

### 7.3 通用异常明细

展开“数据不一致”“簿记作废”“BCT 撤销”记录时，展示数据来源与各异常字段的双方值。

## 8. 历史数据修改

### 8.1 明细结构

历史数据修改的异常明细与处理弹窗使用相同字段和顺序：

| 字段     | 说明                                   |
| -------- | -------------------------------------- |
| 异常项   | 被修改的簿记字段，例如“前端期权费率”。 |
| 数据来源 | 固定为“簿记修改”。                     |
| 原始值   | 修改前、可用于拒绝时恢复的数据。       |
| 修改值   | 业务人员提交的修改后数据。             |
| 提交时间 | 本次修改提交时间，精确到秒。           |

### 8.2 处理规则

1. 交易员打开“处理历史数据修改”弹窗，查看交易编号及修改明细。
2. 交易员选择“同意”或“拒绝”，默认选择“同意”。
3. 点击“确认处理”前，系统弹出二次确认。
4. 同意：将修改值写入当前簿记数据，记录处理结果后关闭异常。
5. 拒绝：将原始值恢复为当前簿记数据，记录处理结果后关闭异常。
6. 同一交易编号存在多个修改指标时，明细按指标逐行展示；本期处理意见默认对该交易的全部修改指标统一生效。
7. 同意且修改值成功落地后，生成历史变更记录并将历史变更信息推送至 Lark。

## 9. 其他异常处理规则

### 9.1 BCT 撤销

1. 操作列显示“作废”。
2. 确认框标题根据开平类型显示“开仓作废确认”或“平仓作废确认”。
3. 提示文案需明确不可恢复，并以独立一行展示“交易编号：xxx”。
4. 确认后移除该异常并提示作废成功。

### 9.2 数据不一致

1. 弹窗展示交易编号、异常类型及字段差异矩阵。
2. 每个异常字段可通过单选组件选择“猎盈值”或“BCT 值”作为最终值；支持一键应用至全部字段。
3. 覆盖原因必填，最多 200 个字符。
4. 点击“确认维护”后弹出“确定修改吗？确定后将覆盖原有值。”二次确认。
5. 确认维护成功后更新最终值，生成历史变更记录并记录覆盖原因。
6. 历史变更记录至少包含交易编号、背靠背合约编号、修改字段、原始值、最终值、来源、处理人、处理时间和原因。
7. 历史变更记录生成后，将本次历史变更信息推送至 Lark；推送内容必须与实际落地数据一致。
8. 数据更新和历史变更记录生成成功后关闭异常；Lark 推送失败时是否阻断该结果，以及后续重试策略，见第 12 节待确认项。

### 9.3 簿记作废

1. 点击“处理”后打开簿记处理抽屉。
2. 抽屉按账户维度维护簿记信息，支持保存全部、保存全部并簿记、保存当前、保存当前并簿记。
3. 必填字段与覆盖原因校验通过后方可提交。

## 10. 数据模型与接口要求

### 10.1 异常记录

```ts
type ApprovalException = {
  id: string
  exceptionType: 'faucon-missing' | 'bct-missing' | 'field-mismatch' | 'historical-data-modified'
  transactionNo: string
  backToBackContract: string
  category: 'opening' | 'closing'
  term: string // {数字}M，由交易或 BCT 数据传入
  underlyingCode: string
  counterparty: string
  account: string
  tradeDate: string // YYYY-MM-DD
  differences: FieldDifference[]
  historicalChanges?: HistoricalChange[]
}

type HistoricalChange = {
  exceptionItem: string
  source: '簿记修改'
  originalValue: string
  modifiedValue: string
  submittedAt: string // YYYY-MM-DD HH:mm:ss
}
```

### 10.2 编号规则

| 编号类型       | 适用场景   | 组成规则                                            |
| -------------- | ---------- | --------------------------------------------------- |
| 背靠背合约编号 | 单上手方   | `{上手方}-OPT-{交易对手名称}-{交易日}-{自增四位数}` |
| 背靠背合约编号 | 多上手方   | `Multi-OPT-{交易对手名称}-{交易日}-{自增四位数}`   |
| 交易编号       | 全部场景   | 待定。                                              |

其中交易日使用 `YYYYMMDD` 八位格式，自增序号为四位；交易编号规则待业务确认后补充。

### 10.3 表字段格式规范

除第 7 节异常列表外，历史变更、变更明细与处理弹窗中的相同业务字段均遵循下表展示格式。

| 字段类别       | 展示格式                                       | 示例                       |
| -------------- | ---------------------------------------------- | -------------------------- |
| 标的           | `{标的名称}({标的代码})`                       | `恒生电子(600570)`         |
| 期限           | `{数字}M`                                      | `3M`                       |
| 日期           | `YYYY-MM-DD`                                   | `2026-08-20`               |
| 日期时间       | `YYYY-MM-DD HH:mm:ss`                          | `2026-09-03 15:26:47`      |
| 金额、名义本金 | 千分位分隔，保留 2 位小数。  | `2,100,000`                |
| 价格           | 保留 2 位小数。                                | `118.00`                   |
| 费率、参与率   | 保留 2 位小数并展示 `%`。                      | `20.50%`                   |
| 无值/未发生    | 使用 `—` 表示。                                | `—`                        |

服务端需保证同一异常仅能被成功处理一次，并返回最新异常统计和记录状态。

## 11. 验收标准

### 11.1 功能与界面验收

1. 页面名称为“簿记审批”，可展示四类异常及总数。
2. 不存在“异常类型”下拉筛选；点击统计卡可筛选列表。
3. 总数卡可恢复全部类型列表。
4. 筛选条件、查询、重置和分页行为符合第 6、7 节要求，默认每页 100 行。
5. 列表包含期限列，所有期限展示为 `{数字}M` 的月份格式，取值由交易或 BCT 数据传入。
6. 历史数据修改展开明细和处理弹窗均包含“异常项、数据来源、原始值、修改值、提交时间”五列，顺序一致。
7. 历史数据修改选择同意后修改值生效；选择拒绝后原始值恢复。
8. 作废确认框展示交易编号，不展示订单编号。
9. 表格主体占满剩余可视区域，分页区距离卡片底部 20px；窗口缩放后不遮挡操作列和分页器。
10. 深色模式下，表单、表头、异常标签和统计卡保持可辨识的前景与背景对比。

### 11.2 业务规则验收

| 编号 | 场景 | 验收标准 |
| --- | --- | --- |
| B-01 | 异常生成 | 簿记作废、BCT 撤销、数据不一致、历史数据修改四类场景能够按照定义准确生成对应异常，不得错分或重复生成。 |
| B-02 | 多字段异常 | 同一交易编号存在多个异常字段或修改项时，必须归属于同一笔交易，并完整展示全部异常项。 |
| B-03 | 数据不一致处理 | 交易员选择最终值并填写原因后，审批结果应准确覆盖已簿记数据；未填写原因不得提交。 |
| B-04 | 历史数据修改处理 | 同意后修改值生效；拒绝后恢复原始值；处理完成后异常从待处理列表移除。 |
| B-05 | 作废处理 | 作废成功后该交易进入最终态，不得再次产生更新记录或执行数据维护。 |
| B-06 | 历史变更准入 | 只有已经审批通过或处理完成的数据才能进入历史变更模块；待审批、已拒绝或处理失败的数据不得进入。 |
| B-07 | 背靠背合约关系 | 一个背靠背合约包含四笔交易时，每笔交易按独立交易编号处理；仅发生变化的交易生成快照，其他三笔不得产生无效快照。 |
| B-08 | 权限隔离 | 簿记审批权限必须独立配置；无权限用户不可查看或操作簿记审批，但不影响其访问待簿记、已簿记和历史变更。 |
| B-09 | 历史追溯 | 可查询同一交易编号的历次变更记录，不得只保留最近一次；记录按变更时间倒序展示。 |
| B-10 | Lark 通知 | 历史数据修改审批通过，以及数据不一致确认维护成功后，均须生成历史变更信息并推送至 Lark。 |
| B-11 | 刷新机制 | 系统每 30 分钟自动刷新一次，并支持手动刷新；刷新不得造成重复记录或丢失已落地数据。 |
| B-12 | 并发处理 | 同一异常被多人同时处理时，仅允许一次成功提交，其他操作应提示数据状态已变化。 |

### 11.3 数据准确性验收

| 编号 | 数据项 | 验收标准 |
| --- | --- | --- |
| D-01 | 异常统计 | 异常总数必须等于四类异常数量之和；点击类型卡后，列表条数和分页总数必须一致。 |
| D-02 | 异常字段 | 开仓、平仓字段必须按照约定字段清单逐字段校验；异常明细只展示存在差异的字段，正常字段不得展示。 |
| D-03 | 来源数据 | 猎盈值、BCT 值、原始值和修改值必须与对应来源系统完全一致，不得因前端格式化改变实际数值。 |
| D-04 | 审批落地 | 审批完成后，已簿记数据必须与审批确定的最终值逐字段一致，准确率要求为 100%。 |
| D-05 | 全量快照 | 每次有效变更必须保存该交易当时的全量字段快照；未修改字段应继承上一版本值，不得为空或被重置。 |
| D-06 | 更新标识 | 最新记录为更新时，仅本次实际修改的字段标红；即使修改前后展示值相同，只要本次修改事件包含该字段，也必须标红。 |
| D-07 | 作废标识 | 最新记录为作废时，该作废行除变更时间、变更类型、来源、变更人、审批人、原因和审批时间外，其他业务字段全部标红；上一条更新记录不得标红。 |
| D-08 | 审计信息 | 每条变更必须完整记录来源、变更人、变更时间、审批人、审批时间和原因，任一字段缺失均不通过验收。 |
| D-09 | 版本顺序 | 同一交易的变更记录必须按变更时间正确排序；相同变更事件不得重复生成版本。 |
| D-10 | 编号一致性 | 父表、变更明细、审批记录和已簿记数据中的交易编号、背靠背合约编号必须完全一致。 |
| D-11 | 数据格式 | 日期、日期时间、金额、价格、费率、期限和空值展示必须符合第 10.3 节表字段格式规范。 |
| D-12 | 查询与分页 | 查询、筛选、分页及刷新前后的数据集合必须一致，不得重复、遗漏或串入其他交易的数据。 |
| D-13 | 拒绝恢复 | 修改被拒绝后，各业务字段必须恢复至审批前原始值，并与审批前快照逐字段一致。 |
| D-14 | 作废终态 | 作废时间之后不得存在同一交易编号的更新快照；发现后续更新即视为数据错误。 |
| D-15 | Lark 数据一致性 | Lark 消息中的交易编号、背靠背合约编号、修改字段、原始值、最终值、处理人、处理时间和原因必须与历史变更记录及最终落地数据完全一致。 |

### 11.4 验收数据集

验收数据至少覆盖以下场景：

1. 单字段更新。
2. 同一交易多字段更新。
3. 修改事件发生但修改前后展示值相同。
4. 多次更新后作废。
5. 同一背靠背合约四笔交易中仅一笔发生变化。
